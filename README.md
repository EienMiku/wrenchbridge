# Wrench Bridge / 扳手互通

[English](README.en.md) · [下载 / Releases](https://github.com/EienMiku/wrenchbridge/releases) · [反馈问题](https://github.com/EienMiku/wrenchbridge/issues)

当前 **1.21.1 / NeoForge 为 `0.1.0-alpha.9`**，修复[拆卸与旋转的原生音效和方块反馈](docs/alpha9-native-feedback.md)。支持[直接打开随身背包中 AE2 网络工具的原生界面](docs/alpha8-container-menus.md)，无需手动取出或留空物品栏。沿用 [alpha.7 默认交互与原生旋转](docs/alpha7-shared-intent.md)、[alpha.6 机器与配置叠层](docs/alpha6-machines-overlay-recipe.md)、[副手支持](docs/alpha5-offhand.md)、[自适应菜单](docs/alpha3-interface.md)、可配置快捷键及确认的材质。扩充测试包含 27 个模组文件、16 个分区、54 个靶机。手中始终保留通用扳手，G 菜单只修改它的模拟配置；原工具提供能力与实际消耗，选择模式不会移动或转换原工具。

Forge 1.12.2、1.16.5、1.20.1 与 NeoForge 26.1.2、26.2 已移植完整模拟功能，以 **`0.1.0-alpha.10`** 提供独立 JAR。下面的手持模拟、随身容器、双手交互和配方同样适用；各平台的原生协议覆盖与验证范围见 [移植记录](docs/alpha10-ports.md)。1.21.1 继续使用已经验证的 alpha.9。

请按 Minecraft 版本和加载器下载对应文件，并在客户端和服务端安装同一版本。**1.12.2 另需安装 MixinBooter 11.18 或更新版本。** 第三方工具模组均为可选兼容对象，无需全部安装。

## 使用

客户端、服务端安装同一个版本的 JAR。单机只需安装在客户端。各版本是独立构建包，不能混用。

- 通用扳手：`wrenchbridge:universal_wrench`，在工具创造物品栏中；配方见下方。
- 材质为用户绘制、共同微调后确认的原生 16×16；当前文件及来源见 [材质说明](art/final/README.md)。
- **主手或副手持扳手，潜行 + 使用方块**：共享拆卸。通用拆卸无需携带其他模组的工具。
- **通用（拆卸）模式的普通右键**：保持方块原本的交互，例如打开机器界面；不会作为扳手意外旋转机器。选择原工具的模拟模式后，普通右键恢复该模式对应的原生功能，例如配置工具在扳手模式下旋转机械动力传动杆。
- **G 键**（可在控制设置中修改）：打开可搜索、翻页的模式菜单。优先编辑主手通用扳手，否则编辑副手通用扳手；普通右键不打开配置菜单。
- **模拟模式**：选择随身携带的真实工具，通用扳手继续留在原手中。每次调用消耗真实工具的电量、气压或耐久，结束后恢复该工具原有模式。原工具没有互相转换的功能。
- 对支持公开枚举 getter/setter 的工具，菜单还会列出子模式，例如 Mekanism 的配置、清空、旋转、扳手。通用扳手保存自己的选择，原工具保持自己的设置。
- **模拟 AE2 网络工具**：普通右键 AE2 网络设备查看原生网络统计；对空气或普通方块使用时打开原生卡片收纳页。遵循 AE2 的权限和目标判定，真实网络工具可位于普通物品栏、副手或可识别的随身容器中；卡片存取保存回真实工具。
- 遵循游戏的双手顺序：主手动作已生效或拒绝时，不再执行副手。测试副手时可先让主手空着或拿木棍；主手放置方块、进食或打开方块界面可能先消费该次使用。
- `/wrenchbridge diagnose` 输出注册表中被识别为扳手的物品数量。

共享拆卸要求工具处于拆卸模式。为防止目标模组只看静态标签而误拆，非拆卸模式下，对已知外来目标的潜行右键采用保守拦截；在工具所属模组内保留原流程。非潜行操作继续使用真实工具的原生行为。

配方需要 2 个任意锭（`I`）、2 根任意棍（`S`），允许混用不同材料，空白留空。NeoForge 使用 `c:ingots` / `c:rods`，现代 Forge 使用 `forge:ingots` / `forge:rods`，1.12.2 从矿物词典收集 `ingot*`、`stick*` 和 `rod*`：

```text
 I 
 SI
S  
```

## 容器内的真实工具

菜单会向服务端请求随身容器的工具清单，因此精妙背包等将内容存放在服务端的容器也能显示。通过公开物品栏能力读取、模拟取出、实际取出和归还；尊重容器过滤与拒绝规则。没有精妙背包硬依赖。

- 探测玩家物品栏、装备栏和可识别的 Curios 装备中的容器，一层内容；不递归套娃背包，不访问远程箱子。
- 从容器借用能力时，只在调用期间取出真实来源工具，完成后放回原槽位；不需要空玩家物品栏槽位，通用扳手保持在原手中。主手和副手使用相同流程。
- 容器不再随身或拒绝归还时，保留真实工具到玩家物品栏；物品栏满则掉落，避免物品丢失。
- 菜单关闭后仍需要携带原工具，来源消失时拒绝模拟；不会生成替代品。AE2 网络工具的原生界面支持容器来源，移走对应容器或工具会关闭界面；铁砧锤的便携铁砧界面仍要求普通物品栏中的真实工具。
- FE、气压、耐久由实际工具负责。当前没有虚拟工具存档、跨工具共享 FE 池或凭空获得原生功能的机制。

后续可以增加独立模式档案：每种工具保留自己的原生数据，另把共享 FE 池做成可选的能力桥接。气压、耐久和安全绑定仍需要各自适配；这与当前“携带真实工具”的规则是两种可以分别配置的功能。

## 探测及拆卸策略

源工具根据通用 wrench 标签、运行时拆卸能力、少量已知工具 ID 和受限的 wrench/spanner 名称规则识别。锤子、绑定器、配置器不因为名称相似就一律加入；多功能工具根据当前 ItemStack 的能力和模式判断是否允许共享拆卸。

现代版本使用已知协议：AE2、Mekanism 等原生交互流水线，Create `IWrenchable`、PneumaticCraft `IPneumaticWrenchable`、Pretty Pipes 原生扳手入口，以及 AnvilCraft 原生锤子拆卸入口。1.12.2 另外探测 CoFH、BuildCraft、Mekanism 和 AE2 的旧扳手接口，存在时才生成实现类。协议覆盖会因目标模组版本而变化。更多源码依据见 [兼容性调查](docs/compatibility-audit.md)。

每次操作只选择一个入口；拒绝或异常后停止。不会用通用 `destroyBlock` 兜底删除机器。未知目标仍可能通过自身认可的通用扳手标签工作，但不会被强制拆掉。源工具可以广泛探测，目标方块仍需要一个可信的原生协议。

现代版本可用数据包把确认遵循通用 wrench 交互的方块加入 `wrenchbridge:common_wrench_targets`（1.20.1 用 `tags/blocks`，1.21.1 及 26.x 用 `tags/block`）：

```json
{"replace": false, "values": ["example:machine"]}
```

此标签只选择原生交互流水线；它不会为没有拆卸实现的方块创建掉落或删除逻辑。

## 构建

Gradle 统一用 Java 21 运行。按目标版本准备 JDK 8、17、21、25，设置 `JAVA8_HOME`、`JAVA17_HOME`、`JAVA21_HOME`、`JAVA25_HOME`，或传给脚本：

```powershell
.\scripts\build.ps1 -Java8 'C:\JDK\8' -Java17 'C:\JDK\17' -Java21 'C:\JDK\21' -Java25 'C:\JDK\25'
# 只构建一个平台：
.\scripts\build.ps1 -Versions neoforge-1.21.1 -Java21 'C:\JDK\21'
```

产物在 `dist/`，源码 JAR 在 `dist/sources/`。也可在各个 `versions/<平台>/` 目录中运行自己的 `gradlew build`。Linux/macOS 使用 `bash gradlew` 并设置相同 JDK 环境变量。

全部构建完成后可运行 `python scripts/package.py`，校验 JAR、生成 SHA-256 清单，并打包全部版本及 Git 跟踪的源码。新增源码文件需先加入 Git。正式移植版发布使用 `python scripts/prepare_ports_release.py --ref <提交或标签>`，从明确的 Git 版本生成源码归档。打包不会包含开发世界、第三方模组或本机 JDK。

共同探测逻辑在 `common/`，各时代 Minecraft API 在 `versions/` 中独立实现。构建脚本不会启动游戏、安装到已有整合包或修改服务器世界。
