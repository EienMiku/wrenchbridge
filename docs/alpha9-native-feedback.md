# 0.1.0-alpha.9：拆卸与旋转的原生反馈

Minecraft 1.21.1 / NeoForge。修复前的实际客户端复现显示：AE2 原版网络工具拆卸时，操作者触发 1 次原音效；模拟网络工具虽然成功拆卸，操作者音效为 0。AE2 原生服务端发声会排除操作者，依赖操作者客户端的预测播放；桥接操作由服务端执行，因此漏掉了这一份声音。

本次为桥接拥有的服务端操作记录操作者。原生位置音效和实体音效只在原调用排除该操作者时调整收件人；保留原音效、类别、音量、音高、范围与取消逻辑。原工具及默认通用模式已经走完整原生预测的路径不进入这个作用范围，继续沿用原来的本地播放和服务端排除规则。

方块事件在原广播入口记录，作用范围结束时只向操作者补发缺失的副本。若同一操作里已有一条相同的方块事件包含操作者，则不补发，避免某些原生拆卸流程同时调用 `playerWillDestroy` 和 `destroyBlock` 时叠加破坏声与粒子。保留事件的维度、位置、范围和原生取消规则，旁观者仍接收原来的广播。没有再次执行拆卸或破坏方块。

气动工艺的共享拆卸直接调用原生方块协议，之前遗漏了原扳手外围的发声步骤。现在成功后复用原扳手的发声入口及其原生声音包；原气动扳手和模拟气动扳手在自己机器上的气压消耗及发声流程继续走原入口，避免再次扣费或重复发声。

真实按键流程的检查还发现：潜行时，部分机器会先消费空主手的交互，导致副手通用扳手没有执行。现在空主手在这一情况下返回 PASS，让游戏继续尝试副手；主手有物品时保留原来的优先级。客户端检查通过 Minecraft 的正常使用入口执行，并观察实际挥手调用。

模拟铁砧锤的拆卸现在由客户端播放一次挥手。此前桥接返回值还会让服务端向操作者回送一次挥手包，造成重复；现在沿用原锤子一次挥手的表现。

逐项对照的 15 把工具：AE2 网络工具、石英扳手、Mekanism 配置工具、Create 扳手、铁砧锤、气动扳手、Pretty Pipes 扳手、Refined Storage 扳手、Yeta 扳手、Powah 扳手、Smart Wrench、Menril 扳手、Modern Dynamics 扳手、Pipez 扳手、Supplementaries 扳手。测试比较原生入口、模拟主副手和适用的共享拆卸，记录原生音效、方块事件、旋转粒子入口和最终方块状态。

| 路径 | 处理 |
| --- | --- |
| AE2 拆卸 | 为服务端模拟补全操作者的原音效 |
| Modern Dynamics、Powah 拆卸 | 同类位置音效排除问题纳入统一修复 |
| Supplementaries 旋转 | 补全方块旋转声与工具实体声；保留原生旋转粒子发送 |
| 气动工艺共享拆卸 | 补上原生发声入口，沿用声音包 |
| Create、Pretty Pipes | 原来已广播到操作者的音效继续保持原次数 |
| 铁砧工艺、Ender IO 等方块事件 | 检查并补全操作者缺少的破坏反馈，避免已有反馈叠加 |
| Refined Storage 代表方块 | 本轮服务端自动化场景中原扳手也拒绝拆卸；只确认拒绝一致，允许路径仍需真人对照 |
| 其余原生入口 | 对照其实际反馈，保持原工具的行为 |

服务端完成 71 组反馈对照，覆盖上述 15 把工具，并复测既有的主副手、保护拒绝、消耗与容器菜单检查。报告见 `feedback-verification.json`、`client-render-verification.json`、`alpha9-verification-result.txt` 和 `alpha9-client-verification-result.txt`。服务端使用原模组协议比较；独立离线客户端完成 53 个场景，验证实际收到的音效，并检查主副手、背包来源、共享模式、保护拒绝及挥手。测试代码和观察器不包含在发行 JAR 中。

网络工具的背包来源与卡片保存、默认交互隔离、原生模式、配方、材质和快捷键沿用 alpha.8。其余五个平台仍为 alpha.1，本次修复仅面向 1.21.1 / NeoForge。更新现有实例仅替换本模组 JAR，保留存档、按键和启动器内存设置。
